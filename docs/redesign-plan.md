# スプーンアプリ 作り直し方針

パラメータを入力すると木のスプーンの3Dモデルが生成される Web アプリの再設計方針。
旧アプリは「生成される形がスプーンらしくない」ため作り直す。

## 1. 前提・要件

| 項目 | 内容 |
|---|---|
| 目的 | パラメータ入力でスプーンの3Dモデルを生成する Web アプリ |
| 最重要出力 | **編集可能な3Dデータ**(Rhino 等の CAD で開ける形式) |
| あれば嬉しい出力 | 実寸の型紙(上面図・側面図)の印刷/PDF |
| 利用者 | 制作者本人 + **講座(スプーンクラブ)の参加者** |
| 利用環境 | ブラウザのみで完結。参加者はスマホ利用を想定 |
| 旧アプリの問題 | 形がスプーンらしくない(旧コードは現存せず、参考にしない) |

## 2. 問題点の洗い出し — なぜ「スプーンらしくない」形になるのか

旧コードは失われているため、この種のパラメトリック生成アプリが失敗する典型原因として整理する。
作り直しでは以下を潰すことを設計の柱にする。

### 2.1 プリミティブの合成で形を作っている(最有力の原因)

楕円体(匙面)+ 角柱や円柱(柄)を並べて繋ぐ方式だと、

- 匙面が「卵を半分にした形」になり、実際の匙面(縁に向かって浅くなる、先端と手前で深さが違う)にならない
- 首(ネック)で部品同士の境目が折れて見える
- 柄が真っ直ぐな棒になり、実物にある反り・厚みの変化がない

→ **部品の合成ではなく、1本の連続した曲面としてスプーンを定義する必要がある。**

### 2.2 断面と曲線の「なめらかさ」が保証されていない

スプーンの美しさは、匙面→首→柄と流れる輪郭線と断面変化の連続性で決まる。
折れ線的な補間や少ない分割数のメッシュでは、光を当てたときに面がうねって見える。

### 2.3 パラメータが作り手の言葉と対応していない

「幅の倍率」「高さスケール」のような幾何学的パラメータでは、動かしても欲しい形に近づけない。
作り手が考える単位——全長、匙面の長さ・幅・深さ、首の位置と太さ、柄の反り(クランク)、縁の厚み——で操作できる必要がある。

### 2.4 「正解の形」を基準にしていない

ゼロから数式で形を作ると、デフォルト値の時点で既にスプーンに見えない。
実績のある型紙(講座で使っているスプーン型紙 .ai / .3dm が Drive にある)から寸法・輪郭を採寸し、**デフォルト値=実在する良いスプーン**になるようキャリブレーションする。

### 2.5 出力がなかった(見るだけだった)

画面で回して見られるだけでは制作に使えない。今回は編集可能な3Dデータの書き出しを最初から要件に入れる。

## 3. 作り直しの方針

### 3.1 形状生成: 「背骨 + 輪郭 + 断面」のロフト方式

スプーンを次の3種類の曲線から1つの連続曲面として生成する。

1. **背骨曲線(側面視)** — 匙面の底から柄の端までの中心線。柄の反り・クランク角はここで決まる
2. **平面輪郭曲線(上面視)** — 匙面の丸み〜首のくびれ〜柄の広がり。左右対称のベジェ/NURBS 曲線
3. **断面形状** — 匙面部は「皿状(上が凹)」、首〜柄は「丸みのある矩形/楕円」。位置に応じて断面をなめらかにモーフィングさせながら背骨に沿ってロフトする

これにより首の折れ目は構造的に発生せず、匙面も実物のような掘り込み形状になる。

### 3.2 パラメータ設計: 作り手の言葉で10個前後

| パラメータ | 例(デザートスプーン) |
|---|---|
| 全長 | 180 mm |
| 匙面の長さ / 幅 | 55 / 40 mm |
| 匙面の深さ | 8 mm |
| 縁の厚み | 3 mm |
| 首の位置 / 太さ | 全長の35% / 10 mm |
| 柄の幅 / 厚み | 14 / 8 mm |
| クランク角(柄の反り) | 12° |
| 柄端の形(丸/角/しゃもじ型) | 丸 |

- スライダー操作で3Dプレビューが即時更新
- **プリセット**を用意(ティースプーン / デザートスプーン / サーバー / 杓子 など)。Drive にある講座用型紙を採寸してプリセット化する
- パラメータ一式は JSON として保存・URL 共有可能にする(参加者が QR コードから開いて自分のデザインを保存・共有できる)

### 3.3 出力

| 形式 | 用途 | 実装 |
|---|---|---|
| **STL / OBJ / GLB** | 3Dプリント・Blender等での編集・汎用ビューア(実装済み) | Three.js のエクスポータでメッシュを書き出し |
| 型紙 SVG / PDF | 上面図・側面図を**実寸100%**で印刷し、材に貼って木取りに使う | 生成曲線を2Dに投影して SVG 化 |
| パラメータ JSON / 共有URL | デザインの保存・再編集・共有 | クエリ文字列にエンコード(実装済み) |

方針変更: Rhino 専用の .3dm ではなく汎用形式を優先することにした(STL/OBJ/GLB 実装済み)。
CAD で編集可能な NURBS(STEP 等)が必要になった場合のみ、OpenCascade.js の導入を検討する。

### 3.4 技術構成

- **フロントのみの静的サイト**(サーバー・DB なし)。ホスティングは GitHub Pages
- 3D 表示: **Three.js**
- NURBS 生成と .3dm 書き出し: **rhino3dm.js**
- ビルド: Vite + TypeScript
- スマホ対応必須(講座参加者はスマホ利用)。UI は日本語

### 3.5 開発フェーズ

- **Phase 1: 形の核** — ロフト方式の形状生成 + 3Dプレビュー + スライダーUI。「デフォルトで既にスプーンに見える」ことがゴール
- **Phase 2: 出力** — STL / .3dm 書き出し、パラメータの保存・共有URL
- **Phase 3: 講座向け仕上げ** — プリセット、実寸型紙 PDF、スマホUI磨き込み、GitHub Pages 公開

## 4. 決めごと・確認したいこと

- Drive の「スプーン型グリーンウッドワーク講座用 .3dm / 型紙 .ai」をデフォルト形状のキャリブレーションに使ってよいか
- 匙面の内側(掘り込み)まで3Dで再現するか、外形のみか(グリーンウッドワークでは掘りは現物合わせのため、外形+掘り込みガイド線でも足りる可能性)
- 対象とする器種の範囲(スプーンのみか、杓子・バターナイフ等まで広げるか)
